# Experience truth

Read `PRODUCT.md`, `DESIGN.md`, and `docs/sane/contracts.md`; use existing `impeccable`
with `sane-experience` for the relevant design task. The Android APK uses a web-rendered
interface, so design semantic DOM behavior as well as Android navigation and insets.

- Prioritize Scan, Monitoring, and Learn. Result/alert details are contextual destinations.
  The bounded recent-alert summaries live within Monitoring; there is no full inbox/history dashboard.
- Monitoring must be prominent in the demo. Show SMS, chat access, selected sources, model readiness,
  and alert delivery as separate states; a desired toggle is not proof of operational protection.
- Use High concern, Use caution, No obvious warning signs, and Unable to assess. Never use Safe,
  guaranteed protection, fabricated accuracy, or a universal All apps protected badge.
- Provide Filipino and English strings without claiming mixed-language detection is validated.
  Preserve source messages unchanged; review translations for safety meaning.
- Use Material-inspired components, Android Back behavior, 48 dp-equivalent touch targets,
  text+icon risk cues, contrast checks, text scaling, screen reader labels, and keyboard insets.
- Keep phishing URLs inert and sensitive text out of lock-screen notifications and Figma fixtures.
- Prototype permissions as labeled representations with return-from-Settings states. Figma clicks,
  simulated alerts, and browser previews are not evidence of native capture or inference.
