# Sane system boundaries

Read `docs/planning/scope.md`, `docs/planning/architecture.md`, and the relevant
`docs/sane/` contract. Confirmed user requirements outrank the older attached proposal.

- Preserve manual paste, automatic SMS, and automatic selected-chat notification analysis.
  A blocked core flow is a blocker, not permission to relabel it as optional.
- Use the documented React/Vite + Capacitor APK direction, native Java capture/inference,
  and a trained local classifier baseline. Version pins, model quality, SDK support, and
  chat-app adapters require evidence. Propose changes through integration with a decision record.
- Both input paths call the same native analyzer. Do not rely on a hidden WebView, JavaScript
  timers, cloud inference, or perpetual polling to keep monitoring alive.
- SMS capture permission, chat notification access, and warning-notification permission are
  separate capabilities. Display states independently, including unknown observations, listener
  connection, app-level notification enablement, and warning-channel block/importance.
- Never equate notification monitoring with reading an entire chat inbox or every message.
  Redacted, missing, unsupported, and truncated content cannot receive a reassuring assessment.
- Current planning is not implementation evidence. A rule-only fallback is explicitly labeled
  degraded behavior and cannot be represented as the completed Local AI detector.
- Follow existing role sessions and coordination receipts. Only integration changes shared
  contracts/configuration. This rule creates no assignment or publishing authority.
