## Procedure

1. Read product truth, proposed/approved visual authority, shared state contract, and assigned scope. Load existing impeccable and the relevant command; preserve vendored skill content.
2. Keep Scan, Monitoring, Learn and contextual results; monitoring is visible core scope. Do not add login/chatbot/full-inbox/fake dashboard features.
3. Design consent plus separate SMS/chat/warning/model states, selected sources, pause, denied/revoked access, listener disconnection, Settings return, partial input, and expired details.
4. Derive readiness from native contract fields, never a desired toggle. Annotate OS permission frames and automatic Figma transitions as simulated representations.
5. Use cautious concern labels and evidence provenance; no Safe badge, fictional percentage, verified sender, or automatic phishing-link navigation.
6. Use Filipino/English string IDs with reviewed safety translation; preserve original text and expansion. Apply Material-inspired controls, Android Back/insets, semantic DOM/TalkBack, contrast, text scaling, dark mode, and reduced motion.
7. Deliver reusable tokens/components/variants and clickable manual/automatic/setup-recovery flows mapped to runtime IDs, with synthetic content and documented pending integrations.
8. Connect real bridge only within assigned implementation; follow Impeccable approval/build/audit and self-validate. Report APK/device versus Figma/browser evidence and open decisions. External Figma writes need applicable user authority and tools.
